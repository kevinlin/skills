Gap Register — BPMN vs. RFP / Detailed Requirements

# Gap Why It Matters Severity Workstream
CTR-01 Approval SLA contradicts the RFP
RFP §5 gives approvers 2 business days to decide; FR_W03 gives them 5 business days, a 2.5× difference. Escalation timing cannot be designed until one figure is chosen.		 Escalation timers and the customer SLA report are built against one figure, so the bid cannot price both. Critical WS4
BPM-01 No timeout path on the approval task
Task_Approve has no boundary timer, so a request nobody decides stays open forever (FR_W03).		 Without a timeout the SLA in FR_W03 cannot be enforced and open requests pile up silently. High WS4
BPM-02 Rejected approvals dead-end
Task_ApprovalRejected has no outgoing flow and no end event, and the requester is never told (FR_W04).		 A rejected quote stalls with no owner, which breaks the process at runtime. High WS4
W-01 One approver per role, no delegate
Each approver role has a single named user and no fallback during absence (FR_W02).		 The first holiday leaves requests unrouted at go-live. High WS4
AMB-01 Approver vs Authoriser
FR_W02 says "Approver"; FR_W05 says "Authoriser". The glossary lists no synonym.		 If these are two roles the routing table is incomplete; if one, the spec should say so. Medium WS4
BPM-03 Approval decision has no data object
The decision and the approver's comment are not written to a data object in the BPMN (FR_W04).		 The audit trail the requirements ask for has nothing to read from. Medium WS4
G-01 Notification wording not specified
No requirement sets the wording of the approval notification email (FR_W01).		 Wording can be settled during build. Low WS4
